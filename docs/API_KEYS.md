# API Keys Management (Phase 2)

`/api/v1/keys` endpoints provide secure key CRUD, health monitoring, and operational checks.

## Endpoints

- `GET /api/v1/keys` - list keys (masked values)
- `POST /api/v1/keys` - create key
- `PUT /api/v1/keys/{key_name}` - update key value or expiry
- `DELETE /api/v1/keys/{key_name}` - delete key
- `POST /api/v1/keys/{key_name}/validate` - validate a single key
- `GET /api/v1/keys/health` - aggregate health and per-key status
- `POST /api/v1/keys/health/check` - run validation cycle and return health payload

All endpoints require admin JWT (`Depends(get_current_admin)`).

## Health Monitoring

`GET /api/v1/keys/health` returns:

- `total_keys`
- `valid_keys`
- `invalid_keys`
- `expiring_soon` (<= 7 days)
- `rotation_required`
- `keys[]` with `name`, `type`, `status`, `last_validation`, `expires_in_days`

## Hot-Reload

`KeyManager.watch_for_changes()` supports:

- `watchdog` observer (if dependency is installed)
- mtime polling fallback (default 5 seconds)

On key change, router invalidates in-memory key cache and refreshes provider instances.

## Alerting

`KeyAlertManager` checks keys every 6 hours and emits alerts for:

- expiring keys
- repeated failed validations
- rotation-required state

Operational controls:

- throttling: 1 hour per same key/rule
- escalation: 3 warnings -> critical

## Dashboard

`dashboard/pages/10_API_Keys.py` provides:

- key CRUD and single-key validation
- Keys Health section
- status distribution pie chart
- expiring keys table sorted by `expires_in_days`
- Run Health Check action

`dashboard/main.py` provides API Keys Status widget with 30s auto-refresh.

## Notes

- Environment variables (e.g. `OPENAI_API_KEY`) override encrypted storage values.
- Validation cache TTL is 15 minutes with LRU capacity 100 entries.
- Validation calls are rate-limited per key/provider.

## Windows DPAPI

- On Windows, `KeyManager` tries to protect master key using DPAPI (`CryptProtectData` via ctypes).
- If DPAPI is unavailable or fails, storage falls back to file-based master key format.
- Existing plaintext/base64 master key files are auto-migrated to DPAPI envelope when possible.
- Setup scripts:
  - `scripts/setup_windows_keys.bat`
  - `scripts/setup_windows_keys.ps1`

## Migration and Backup Tools

- `scripts/migrate_env_to_encrypted.py`
  - Discovers `*_API_KEY` values from env and `.env`
  - Dry-run by default (`--apply` to execute)
  - Creates `.env.backup_<timestamp>` and rolls back on failure
- `scripts/backup_keys.py`
  - Creates encrypted backup (`.vkb`)
  - Optional extra password layer (`--password`)
- `scripts/restore_keys.py`
  - Validates backup then restores with `merge` or `replace` strategy
- `scripts/validate_backup.py`
  - Checks format, checksum, and decryption compatibility

## Scheduled Backups

Configure in `configs/vagus.yaml`:

```yaml
key_backup:
  enabled: true
  schedule: "0 2 * * *"
  retention_days: 7
  encryption_password: null
  backup_dir: "~/.vagus/backups"
  max_backups: 10
```

- Backups are generated by `KeyAlertManager` scheduler.
- Retention cleanup removes old backups by age and maximum count.
